# Assetz Property Group — luxury real-estate website

A fast, fully static marketing site with a serverless lead API. Every page is generated from structured data, so project facts live in one place and every page shares the same header, footer, mega menu and design system.

## Why this stack

- **Static HTML generated by a ~100-line Node script (`build.js`)**: no framework runtime, no client bundle. Pages load instantly on mobile, which matters most for property-lead campaigns, and there is nothing to patch or upgrade.
- **Template modules in plain JavaScript** (`src/templates/*.js`): one reusable component per concern (layout, lead form, project template, cards).
- **One serverless function** for leads (`api/lead-core.js`), wrapped for Netlify and Vercel. Secrets stay on the server.
- **Zero npm dependencies** for the site itself. Playwright is used only for the QA scripts and to render the PDF guide.

Requires Node 18 or newer.

## Commands

```bash
node build.js              # generate dist/ (22 routes + sitemap.xml + robots.txt + 404)
node server.js             # preview on http://localhost:4173 with a working /api/lead (stores leads in ./leads/leads.jsonl)
node scripts/make-guide.js # regenerate the homebuyer's guide PDF from data/guide.json
node scripts/qa.js out/    # crawl every route at desktop + phone: console errors, overflow, broken links, h1 count
node scripts/test-leads.js # end-to-end lead tests (API validation + browser form flows); run while server.js is up
```

## Content and data

All content is in `data/`:

- `projects.json`: every project fact, with `sourceUrl`, `sourceDate`, and `conflicts` / `*Note` fields recording discrepancies in the developer's own sources. Fields the developer does not publish are stored as `"Not Mentioned"` or `"Price on Request"` and rendered that way.
- `company.json`: verified company statistics, milestones and awards.
- `site.json`: contact details, navigation, social links, tracking IDs, legal notices.
- `blogs.json`, `faqs.json`, `guide.json`, `about.json`: editorial content.

Edit the JSON, run `node build.js`, deploy `dist/`.

## Lead capture and CRM

Every form posts JSON to `/api/lead`. Forms: homepage consultation, popup (Enquiry / Request Brochure / Book a Site Visit, project preselected), project inline + sidebar, contact (with NRI and enquiry type), blog sidebar, and the lead magnet.

Captured: name, mobile with country code, email, project, enquiry type and subtype, purpose, preferred time, message, consent text and timestamp, source page URL, first-touch UTM source/medium/campaign/content/term (persisted for the session), and server receipt time.

Server-side (`api/lead-core.js`): validation and sanitisation, honeypot, per-IP rate limiting, origin check, duplicate flagging (same phone + project + type within 24 h is forwarded with `duplicate_of`), project-code mapping, idempotency key, and an 8-second timeout to the CRM.

**Configuration (environment variables on the host; never in frontend code):**

| Variable | Purpose |
|---|---|
| `CRM_WEBHOOK_URL` | HTTPS endpoint receiving each lead (e.g. the ScaleTrack inbound webhook) |
| `CRM_API_KEY` | Sent as `Authorization: Bearer …` |
| `CRM_PROVIDER` | `scaletrack` wraps the payload as `{ lead, source }`; default sends a flat object. Adjust field names in `toCrm()` once the CRM schema is confirmed. |
| `ALLOWED_ORIGINS` | Comma-separated origins allowed to post (default: same host) |
| `RATE_LIMIT_MAX` | Submissions per IP per 10 minutes (default 8) |
| `IP_SALT` | Salt for the stored IP hash |

**Pending configuration:** no CRM credentials were provided, so `CRM_WEBHOOK_URL` is unset. In that state the hosted function validates and logs each lead to the function logs and the visitor sees the thank-you page, but **leads do not reach a CRM**. Set the two CRM variables before running campaigns. Forwarding was verified against a local mock webhook (bearer auth, idempotency key and full payload received). The in-memory rate-limit and duplicate windows are per function instance; back them with Redis or KV if traffic warrants it.

Downloads: the guide PDF (`assets/downloads/bengaluru-premium-homebuyers-guide.pdf`, 11 pages, generated from `data/guide.json`) and the Muse & Maison e-brochure (published by the developer) are returned only after a successful submission and shown on `/thank-you/`.

## Tracking

Set `tracking.gtmId` in `data/site.json` to load Google Tag Manager; configure GA4 and the Meta Pixel inside GTM. The site pushes these `dataLayer` events, once each per action:

`lead_submit` (with `enquiry_type`, `project`, `lead_id`), `brochure_request`, `site_visit_request`, `guide_download`, `lead_error`, `enquiry_open`, `finder_search`, `click_to_call`, `whatsapp_click`, `consent_granted`, `consent_denied`.

Use `consent_granted` as the GTM trigger condition for analytics and advertising tags so they fire only after consent.

## SEO

Unique title, description, canonical and Open Graph tags per page; `sitemap.xml` and `robots.txt` (thank-you excluded); breadcrumbs; JSON-LD for `RealEstateAgent`, `Residence`, `FAQPage`, `BlogPosting`, `BreadcrumbList`, `AboutPage`, `ContactPage`. Set `baseUrl` in `data/site.json` to the production domain before building.

## Deployment

- **Netlify:** connect the repo with base directory `website`. `netlify.toml` sets the build, publish folder, function directory and cache headers; `dist/_redirects` maps `/api/lead` to the function. Add the CRM environment variables.
- **Vercel:** set the root directory to `website`. `vercel.json` sets the build and output; `api/lead.js` is picked up as a serverless function.
- **Any static host + separate API:** deploy `dist/` and point `leadEndpoint` in `data/site.json` at your lead endpoint.

## Testing summary

- `scripts/qa.js`: 22 routes × desktop (1440) and phone (390): no console errors, no failed requests, no horizontal overflow, exactly one `h1` per page, no placeholder links; 23 internal link targets, 0 broken.
- `scripts/test-leads.js`: API returns 422 with field errors for missing consent, invalid phone/email and unknown project; honeypot dropped; guide and brochure downloads returned; NRI (+971) accepted; duplicate flagged; browser flows for homepage enquiry, project brochure popup (project preselected) and guide download all reach `/thank-you/` with the right download; finder → filtered listing → empty state → clear filters.
- CRM adapter verified against a mock webhook (auth header, idempotency key, mapped payload).
- Google Maps embeds were not testable in the sandbox (blocked network); they load normally on a public host.
